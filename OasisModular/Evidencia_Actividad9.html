1. Descripción del Requerimiento (Actividad 4)

Se solicitó implementar el guardado transaccional de una entidad Cabecera (Contrato) junto a sus entidades Detalle (DetalleContrato), aplicando reglas de negocio estrictas utilizando la anotación @Transactional para asegurar la atomicidad de la base de datos (rollback en caso de fallo).

2. Implementación de @Transactional en Servicio

Se modificó el servicio ContratoServiceImpl.java. Al formalizar el contrato, se asegura que la habitación esté disponible. Si ocurre un error al procesar el detalle (por ejemplo, el cálculo de la garantía falla), todo el proceso hace rollback.


@Service
@RequiredArgsConstructor
@Transactional
public class ContratoServiceImpl implements ContratoService {
    
    private final ContratoRepository contratoRepository;
    private final HabitacionRepository habitacionRepository;

    @Override
    @Transactional(rollbackFor = Exception.class)
    public ContratoResponse formalizarContrato(ContratoRequest request) {
        // 1. Validar disponibilidad
        Habitacion habitacion = habitacionRepository.findById(request.getHabitacionId())
            .orElseThrow(() -> new ResourceNotFoundException("Habitación no encontrada"));
            
        if (!"DISPONIBLE".equals(habitacion.getEstado())) {
            throw new BadRequestException("La habitación no está disponible para alquilar.");
        }
        
        // 2. Guardar Cabecera
        ContratoResidencia contrato = new ContratoResidencia();
        // ... (Mapeo de datos de cabecera)
        
        // 3. Procesar y guardar Detalles (Cobro mensual + Garantía obligatoria)
        for(DetalleContratoDTO det : request.getDetalles()) {
            contrato.agregarDetalle(mapearDetalle(det));
        }
        
        // Persistencia (Cabecera + Detalles vía CascadeType.ALL)
        contrato = contratoRepository.save(contrato);
        
        // Actualizar estado de habitación
        habitacion.setEstado("OCUPADO");
        habitacionRepository.save(habitacion);
        
        return contratoMapper.toResponse(contrato);
    }
}

3. Pruebas Unitarias (Validación Transaccional)

Se configuraron las pruebas unitarias usando Mockito y JUnit 5, comprobando que el API arroje 400 Bad Request en caso de violaciones de reglas de negocio, y 201 Created en flujos correctos.


@Test
void formalizar_conHabitacionOcupada_lanzaExcepcion() {
    // Arrange
    ContratoRequest req = new ContratoRequest();
    req.setHabitacionId(101L);
    
    when(habitacionRepository.findById(101L))
        .thenReturn(Optional.of(Habitacion.builder().estado("OCUPADO").build()));
        
    // Act & Assert
    assertThrows(BadRequestException.class, () -> {
        contratoService.formalizarContrato(req);
    });
}
